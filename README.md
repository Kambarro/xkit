## 🎯 Что это

**XKIT** превращает чистый VPS (Ubuntu 24.04+) в готовый VPN-сервер и берёт на себя всё обслуживание:

- ставит панель **3X-UI + Xray** и прячет её за **nginx** — снаружи панель не видна, на «случайный» заход сервер отвечает обычным сайтом;
- настраивает **сертификат** (домен, IP или самоподписанный) и следит за продлением;
- создаёт **протоколы**: VLESS REALITY, VLESS XHTTP, AmneziaWG, Hysteria 2;
- **один пользователь = все протоколы = одна подписка** с общим лимитом и сроком;
- управляет всем через **TUI**, классическое меню, CLI или **Telegram-бота с телефона**;
- подключает **зарубежные ноды** и распределяет трафик: клиент → ваш сервер → каскад → мир;
- делает **бэкапы**, переносит сервер на новую машину, обновляется сам — только подписанными релизами.

## 💡 Философия

- **Снаружи — только нужное.** Панель слушает `127.0.0.1`, наружу смотрят лишь клиентские точки входа и сайт-прикрытие.
- **Один пользователь — одна подписка.** Добавили человека — он сразу во всех протоколах. Добавили протокол — «Обновить подписки», и он у всех. Никакой ручной синхронизации.
- **Не доверяй — проверяй.** Каждый компонент ставится только после сверки SHA-256 и подписи релиза. Не совпало — установка останавливается, а не «продолжает на свой риск».
- **Ошибка = откат.** Конфиг nginx проверяется до применения, обновление ядра — с автооткатом, если панель не поднялась. Перед удалением — обязательный бэкап.
- **Чужое не трогаем.** XKIT не включает молча ваш файрвол, не удаляет чужие правила и сайты, не делает `apt upgrade` за вас.
- **Секреты не утекают.** Пароли и ключи — в файлах с правами 600, передаются через stdin, не светятся в логах, QR и подписки генерируются локально, без внешних сервисов.
- **Автоматика с правом решения.** Опасные операции — только с подтверждением; сроки, алерты и проверки работают сами, но перезагрузку сервера и удаление назначаете вы.

## ⚡ Быстрый старт

### Что понадобится

- VPS с **Ubuntu 24.04+**, доступ `root` по SSH;
- архитектура `amd64` или `arm64`;
- домен **не обязателен** — работают сертификаты для домена, IP и самоподписанный.

### Установка

```bash
curl -fsSL https://raw.githubusercontent.com/kambarro/xkit/main/install.sh | sudo bash
```

Установщик спросит основные параметры, поставит панель, сертификат и сайт-прикрытие, предложит выбрать протоколы и сразу подскажет, как добавить пользователей. В конце выдаст адрес панели, пароли (в `/root/xkit-info.txt`) и подписки.

Автоматически, без вопросов: добавьте `-s -- -y` (поверх существующего — `--force`).

### Перенос сервера из бэкапа

Положите архив `xkit-*.tar.gz` в `/root/xkit-restore/` и запустите установщик — он предложит восстановить всё или по частям (сертификаты, пользователи и панель, ноды). Ноды переподключатся сами, клиенты сохранят свои подписки.

### Запуск

```bash
sudo xkit             # полноэкранный TUI
sudo xkit --classic   # классическое текстовое меню
```

### Обновление

```bash
sudo xkit update
```

Состояние, пользователи и подписки сохраняются. После обновления из TUI интерфейс сам предложит перезапуск («нажмите Enter») — новое меню подхватится сразу. Проверить наличие новой версии без установки: `xkit update --check`.

### Удаление

```bash
sudo xkit uninstall          # xkit + его nginx-сайт; бэкап создаётся обязательно
sudo xkit uninstall --full   # + панель 3X-UI и сертификаты xkit
sudo xkit uninstall --purge  # всё начисто, БЕЗ бэкапа (подтверждение: PURGE)
```

Ваш SSH и файрвол-правила доступа не трогаются; чужие сайты и сертификаты сохраняются (кроме `--purge`).

## 🖥️ Интерфейсы

### TUI

Полноэкранный интерфейс: состояние служб, пользователи, протоколы, ноды, обслуживание. Навигация:

| Клавиша | Действие |
|---|---|
| `↑` `↓` / `j` `k` | перемещение |
| `Enter` | открыть / выполнить |
| `Esc` / `q` | назад, на главном — выход |
| `/` | поиск по разделу |
| `r` | обновить состояние |
| `?` | справка |

Работают и русские клавиши (`о`/`л`/`й`/`к`). Вывод любой команды остаётся на экране до `Enter`. После `xkit update` TUI предложит перезапустить интерфейс, чтобы показать новую версию и меню.

### Классическое меню

`xkit --classic` — то же самое цифрами, для тех, кому привычнее, и для сценариев без TTY (cron, pipe). Шесть групп: установка, пользователи, протоколы, ноды, обслуживание, мониторинг.

### Telegram-бот — управление с телефона

Полноценный админ-интерфейс в Telegram:

```bash
sudo xkit telegram setup    # ключ бота + ваш чат + admin IDs
sudo xkit telegram bot on   # включить службу бота
```

Откройте бота, отправьте `/start` — появится меню с кнопками:

- **👥 Пользователи** — создать, список, подписка и QR, сброс трафика, выключить/включить, удалить (с подтверждением);
- **🖥 Ноды** — состояние, метрики, проверка, смена профиля канала, обслуживание;
- **⏰ Сроки аренды** — сроки мастера и нод, напоминания за 7/3/1 день (раз в сутки, не спам);
- **📊 Статус** — службы, сертификат, диск, короткая сводка;
- **🛠 Обслуживание** — health-check, бэкап, обновление XKIT, перезапуск всего стека (3X-UI/Xray/nginx), ребут сервера — опасное только через «✅ Да»;
- **🔀 Транспорт TG** — состояние каналов доставки.

**Бот работает даже там, где Telegram заблокирован:** если прямой доступ к Telegram API недоступен, сообщения идут через SSH-туннель на зарубежную ноду. Каналы проверяются и восстанавливаются сами (каждые ~20 секунд), при недоступности всех — бот терпеливо ждёт подъёма любого. После ребута сервера бот сам напишет, что мастер снова в строю.

Доступ — только у admin IDs из настройки; остальным бот молчит. Все действия пишутся в журнал.

## 🛡️ Протоколы

Меню: `xkit protocols` (или TUI → «Протоколы»).

| Протокол | Что это | Когда выбирать |
|---|---|---|
| **VLESS + REALITY + Vision** | основной TCP-профиль, маскировка под чужой TLS-сайт | базовый вариант, работает у большинства |
| **VLESS + XHTTP + REALITY** | альтернативный транспорт | если обычный REALITY прижимают |
| **AmneziaWG** | обфусцированный WireGuard (профиль 3.1 Header Protection или классический) | UDP там, где TCP режут; роутеры, AmneziaVPN |
| **Hysteria 2** | быстрый UDP/QUIC с маскировкой Salamander | плохие каналы, мобильные сети |

Что важно знать:

- **Пользователь создаётся сразу во все протоколы** — одна подписка на всё;
- **Выключить ≠ удалить**: протокол можно выключить (как ползунок в панели) — он пропадёт из подписок, но останется в панели; включили обратно — вернулся. То же самое с пользователями;
- **Добавили протокол позже?** «Обновить подписки» (`xkit client bind`) привяжет его всем существующим пользователям;
- REALITY-мастер сам сканирует и предлагает подходящие сайты-прикрытия (свой сайт, скан подсети, проверенный список или вручную);
- XKIT не включает ваш UFW молча: сначала добавляет нужные allow-правила, включение — только с вашего согласия.

> Локальный статус «работает» не гарантирует проходимость у конкретного провайдера клиента — это зависит от сети, региона и репутации IP. Проверяйте реальным подключением.

### Подписки

Каждый пользователь получает:

- **страницу подписки** — открыть в браузере: QR, ссылки, импорт в один клик;
- **прямую ссылку** для v2rayNG / Streisand / Hiddify / v2rayN (base64);
- **`.yaml`** для Clash Verge / FlClash (Mihomo) — с раздельной маршрутизацией: RU-сайты напрямую, остальное через прокси;
- **`.json`** для sing-box;
- **`/amnezia`** — страница с QR и конфигом для AmneziaVPN.

Посмотреть: `xkit client show ИМЯ` или бот → Пользователи → 🔗 Подписка. QR генерируется локально.

## 🌍 Режимы работы

**Одиночный сервер** — всё на одной машине:

```text
клиент → ваш сервер (nginx / REALITY / UDP-протоколы) → интернет
```

**Мастер с нодами** — ваш сервер в РФ + зарубежные ноды:

```text
клиент → мастер → каскад (балансировка) → нода 1 / нода 2 → интернет
```

### Ноды и каскад

- добавление ноды по SSH: `xkit nodes` — XKIT сам поставит панель на ноде, создаст защищённый туннель и настроит балансировку;
- стратегии распределения: `roundRobin`, `random`, `leastPing`, `leastLoad`;
- **профили канала** мастер→нода: VLESS TCP REALITY, XHTTP REALITY, Hysteria 2 — переключение с реальной проверкой скорости и откатом при неудаче (`xkit nodes profile switch`);
- **смена IP ноды** без переустановки (`xkit nodes readdress`);
- мониторинг: трафик, скорость, ping, CPU/RAM каждой ноды — в TUI и боте;
- проверка «заморозки» канала (`xkit nodes freeze`) — подскажет, режет ли провайдер TCP на зарубежном участке;
- удаление последней ноды возвращает сервер в одиночный режим.

Реквизиты каждой ноды — в `/root/xkit-node-ИМЯ.txt` (права 600).

## 🧰 Обслуживание

| Задача | Как |
|---|---|
| Проверить сервер | `xkit health` (глубокая: `xkit health deep` — проба реальным клиентом) |
| Бэкап | `xkit backup` (автобэкапы ежедневно; проверка: `xkit backup verify`) |
| Восстановление | `xkit restore` (сначала можно `--dry-run`) |
| Перезапустить всё | `xkit services restart` (3X-UI/Xray/nginx, бот пришлёт чек) |
| Сертификат перевыпустить | меню «Обслуживание» или бот |
| Версии панели/ядра | `xkit versions list / install / rollback` — только проверенные релизы с SHA-256 и автооткатом |
| Сайт-прикрытие | `xkit camo status / regenerate` — уникальный сайт по seed, без внешних CDN |
| Сроки аренды | `xkit expiry set / list` — напоминания в Telegram |
| Журнал действий | `xkit audit` |
| Диагностический архив | `xkit doctor export` — без секретов, для отправки в поддержку |

## 🔒 Безопасность коротко

- компоненты и обновления — только с проверкой **SHA-256 + подпись релиза Ed25519**; не совпало — отказ;
- панель на `127.0.0.1`, секретный путь, снаружи — nginx и сайт-прикрытие;
- пароли/ключи — файлы `600`, передача через stdin, в логах и snapshot — маскировка;
- SSH к нодам — проверка host key, API панели — pinned TLS;
- `nginx -t` и бэкап перед изменениями, автооткат при ошибке;
- удаление — только с подтверждением и обязательным бэкапом (кроме явного `--purge`);
- бот отвечает только своим admin IDs, опасные действия — через подтверждение.

## ❓ FAQ

**Нужен ли домен?** Нет, можно по IP. Но со своим доменом маскировка естественнее.

**Можно поверх существующего 3X-UI?** Да — XKIT подхватит панель и спрячет её за nginx.

**Чем update отличается от reinstall?** `update` сохраняет всё состояние; `reinstall` — бэкап и установка с нуля.

**Обновил из TUI — меню старое?** Начиная с 8.2.0 TUI сам предложит перезапуск после обновления. На более старых версиях — выйдите и запустите `xkit` заново.

**Telegram заблокирован на сервере — бот будет работать?** Да, через SSH-туннель на зарубежную ноду. Нужна хотя бы одна нода; каналы восстанавливаются автоматически.

**Клиент не подключается — что делать?** `xkit health deep` проверит сервер реальным клиентским подключением. Если сервер в порядке — дело в сети клиента/провайдере: попробуйте другой протокол (UDP-варианты часто живут там, где режут TCP).

**Гарантирует ли XKIT обход блокировок?** Нет. Инструмент настраивает сервер; проходимость зависит от сети, региона и времени. Никаких гарантий.

## 🛠️ Если что-то не так

```bash
sudo xkit health                  # общая диагностика
sudo systemctl status nginx x-ui  # службы
sudo nginx -t                     # конфиг nginx
sudo ls -lt /var/log/xkit-*.log   # журналы
sudo xkit telegram check          # уведомления не приходят?
sudo xkit doctor export           # архив для разбора (без секретов)
```

Несовпадение SHA-256 при установке **не обходите** — убедитесь, что все файлы из одного релиза.
